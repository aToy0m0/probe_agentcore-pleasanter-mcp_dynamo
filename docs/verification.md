# CloudWatch 検証報告

2026年11月10日、`us-east-1`。同じ構成の検証スタックをデプロイし、スタック内の検証 Lambda が Cognito SDK でログインして Gateway に MCP リクエストを送信した。

| 項目 | 実測 |
| --- | --- |
| Gateway への匿名・無効トークン、モック URL への匿名アクセス | 拒否 |
| 2ユーザーの `tools/list` と `tools/call` | 一覧を取得し、各自のモックアカウントを返した |
| クライアントが予約引数を指定 | インターセプターが本人の情報に置き換えた |
| モックが照合できないキー | 拒否 |
| 古い版を使った書き込み | DynamoDB の条件不一致で拒否 |
| 登録解除後の呼び出し | 利用できるキーがない旨を返した |
| キーを再登録 | 正しいモックアカウントで成功 |
| 登録画面と未認証の状態照会 | HTTP 200・CSP あり。未認証の状態照会は HTTP 401 |

自動検証のキー準備・更新・解除は検証 Lambda が保管処理を直接実行した。ブラウザでログインして登録 API に書き込む操作、Codex 自身を MCP クライアントにした OAuth 接続、実 Pleasanter への接続は未実施。登録ハンドラーのローカルテストを含む4件と CDK synth は通過した。

検証後にスタックの削除完了と、KMS 鍵2本の削除予約を確認した。ロググループは5本とも保持期間180日で作成されていた。
